offload.sh: the lite copy now carries a manifest naming its card, and the tool makes both together. New subcommand `lite <new-lite-dir> <copy-dir>` transcodes each video from the verified copy into a folder that does not exist yet (or is empty) and writes the manifest in the same step: card id, each lite file's hash, and the hash of the original it read (a BRAW's Proxy .mp4), checked against SHA256SUMS before and after the transcode. No command writes a manifest for files already in a folder, and `lite` refuses a non-empty folder, the copy, or anything inside it. safe --lite refuses a lite dir with no manifest, a manifest for another card, a changed or unreadable lite file, or lite files with the same bytes for different originals; its refusals say to make a fresh lite folder, never to regenerate. A hand-typed manifest in the same format would still pass: the tool cannot tell.
