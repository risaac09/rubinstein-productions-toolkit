# Resolve traps

> **Status:** operational 2026-11-09. Measured in DaVinci Resolve Studio 21.2, on scripted ` [auto]` timelines in a sandbox project. Each entry says what was seen and what works instead. An entry marked "not tested" is a claim from the scripting docs that nobody here has run.

Other docs cite these by number (`T3`). A number never changes; a corrected trap keeps its number and says what replaced it.

## Timelines and items

- **T1. `AppendToTimeline` clip info.** `endFrame` is exclusive. An item's length is floor((end - start) x timeline fps / source fps). To get n timeline frames, ask for ceil(n x source fps / timeline fps) source frames.
- **T2. Frame rate.** A scripted timeline takes the project frame rate. `SetSetting("timelineFrameRate")` returns False once the timeline exists.
- **T8. Stills.** `ExportCurrentFrameAsStill` wants an absolute path and can return the previous frame. Seek a few frames early, seek to the frame, wait two seconds, then export. Wait longer after a timeline switch.
- **T10. Mixed rates.** `interchange` refuses a manifest whose sources mix 29.97 and 30 fps. It also wants every source at the timeline's rate. A 24 fps timeline from 29.97 or 60 fps sources is built by `assemble_timeline`, which appends each span at its clip's own rate (T1).
- **T12. Fill on a duplicated timeline.** A duplicated timeline set to 1080x1920 with `timelineInputResMismatchBehavior` = `scaleToCrop` reads the setting back and still renders every clip fitted to width. Set the item property `Scaling` to 3 on each item. Values: 0 project, 1 crop at native pixels, 2 fit, 3 fill, 4 stretch.
- **T18. A picture fade reads back; a music fade read back and did not render.** `TimelineItem.SetFades({"FadeIn": n, "FadeOut": n})` returns True on picture and audio items and `GetFades()` reads the frames back. A 12-frame fade-in was confirmed on a still: mean luma 6 at frame 1 against 24 at frame 40. On audio the read-back is all there is: eight masters built with a `SetFades` music fade out all ended on a hard cut (peaks of about -5 dBFS up to the last 50 ms on the meter), although Resolve's own scripting stub documents the call for audio items. The cause is not known. The read-back proves the property round-trips, not that the render fades. `assemble_timeline` therefore does not call it: it cuts the music with ffmpeg into a bed with a one second fade out baked into the file (`rpresolve/musicbed.py`: 24-bit 48 kHz WAV, never a fade over a quarter of the bed) and places that file on A1. `deliver_check` has a `tail` row for the rendered file (the last 100 ms at least 12 dB below the window 3 s to 1.5 s before the end), on for `social_9x16_music`. No tool sets a picture fade; a dip to black is the `dip-to-black` macro or a transition from `ui_steps`. This corrects T11.
- **T11. Fade by menu (fallback).** Before T18 was measured, the working recipe was: make the timeline current on the Edit page, park the playhead where the fade starts, then Trim, Fade Out to Playhead from the menu bar. With nothing selected it fades only the clips under the playhead, so parking past the last picture frame fades the music alone. A timeline's FCPXML export does not carry fades, so there is no file read-back for either route.

## Fusion on a timeline item

- **T3. Stale render.** A Fusion comp built by script passes its read-back and still renders the old picture. Toggling `TOOLB_PassThrough` on and then off on each added tool makes Resolve render it. `apply_effect` does this and checks it.
- **T4. Comp time.** Comp time on a timeline item counts source frames, with 0 at the item's first frame. A macro keyed over 48 frames lasts 48 source frames, which is 1.6 s of a 30 fps source on a 24 fps timeline. `apply_effect` scales a macro's key times by source frames over timeline frames. Checked on a still: a `TimeStretcher` keyed to half speed over a 90-source-frame item showed, 66 timeline frames in, the frame the source holds 1.375 s after the item's start.
- **T5. Retime.** `TimeSpeed` anchors on the clip's source frame 0, so it shows footage from far earlier in the file. A `TimeStretcher` with `SourceTime` keyed from 0 to speed x N does the retime correctly. This is the scripted stand-in for Edit page speed, ramps included.
- **T9. Deleting a comp.** `DeleteFusionCompByName` returned False on an item's only comp. Empty the comp and reuse it. `apply_effect` does: an item whose comps are all emptied `rp-fx` comps (only MediaIn1 and MediaOut1) is built into again, the comp loaded with `LoadFusionCompByName` and renamed, and the plan row says `reuse`. An item with a comp that holds tools, or any comp not named `rp-fx ...`, is still refused. Empty a comp by deleting its tools in the Fusion page; not yet run live, so whether `GetToolList` answers for a comp that is not open on the Fusion page is unchecked.
- **T13. Spline handles.** The `RH` and `LH` handles in `SetKeyFrames` are offsets from their key. Absolute values overshoot.
- **T14. A pan that follows a subject.** A `Transform` on the item, `Center` given an `XYPath` modifier, a `BezierSpline` on its X keyed from 0.5 + c0 - start to 0.5 + c0 - end over the item's source frames. c0 is the crop centre the item's own Pan holds.
- **T22. Text+ fonts.** The family "Arial Black" set by script renders nothing. "Arial" with the style "Bold" works. Choose the real face in the Inspector.
- **T23. Gain is linear light.** In a colour-managed project a linear gain ramp from 1 to 0 looks like a late snap. Key a dip in even stops (1, 0.5, 0.25, 0.125, 0.06, 0.02, 0).
- **T24. Transitions are scriptable.** `TimelineItem.AddTransition({type: 'Cross Dissolve', category: 'simple', position: 'end', alignment: 'center', duration: n})` returns the transition item, or None when the cut has no handles. Read `GetDuration()` back: a short handle would shorten the dissolve without a word. Measured 2026-11-09: three 2-frame Cross Dissolves added on a 48-item timeline, each read back at 2 frames.
- **T25. A key before frame 0 gets a twin at 0.** When a spline's first keyframe is set at a negative comp frame (an end-anchored macro on an item shorter than the macro), Fusion adds a key at frame 0 with the curve's value there. Harmless to the picture; a read-back that counts keys must allow it. Measured 2026-11-10: `dip-to-black` on a 90-frame item (112 source frames) read keys at [-97, 0, 88, …, 111] for a macro moved to [-97, 88, …, 111]; gain sampled 1.0 through frame 88 and 0.0 at 111.
- **T26. A still is the source frame.** `Project.ExportCurrentFrameAsStill` writes the clip at its own size (3840×2160 from a 1080×1920 timeline), with the grade but without the timeline's size, Scaling or Pan. It cannot prove a 9:16 frame. Resolve's own MCP `get_image` with source `timeline` renders at the timeline's output size; a template match of that render inside the 16:9 still measured the window at the planned centre (cx 0.462 for 0.47 asked, correlation 0.998, 2026-11-10).
- **T28. A draft's flash was not the macro's.** The draft farm drew `exposure-flash` as an added brightness of 0.3; the macro multiplies by its gain in linear light (T23). On a bright day shot the two look alike; on a dark night shot the macro lifts mean luma from 49 to 65 where the old draft showed about 119, whatever the gain. Measured 2026-11-10 on a 5-frame item: gain 10 keyed to 1 over the macro's span matched that draft (117 on the first frame). A flash on an item shorter than its span never returns to normal inside the item, in the draft and the build alike. `apply_effect` takes `gain` (1 to 20, default 2) for `exposure-flash`: pass 10 to match a draft on a dark shot, 2 or 3 on a bright one, and compare one rendered frame against the draft before committing a value. Judge a flash against an unflashed render of the same frame, never the item's first frame against its last. **Since 2026-11-10 one number serves both.** A fill's `gain` goes through `methods.to_manifest` as `params.gain` on the flash entry (a gain on any other slot is refused), `apply_effect` writes it into the macro, and the draft draws the same gain falling to 1 over 12 frames. The draft cannot do linear light, so it multiplies the encoded levels by gain^(1/2.55), which is the same thing on a power-law display. The 2.55 is the calibration: on a flat frame of luma 49, a gamma of 2.45 fits the macro's 65 at gain 2 and 2.64 fits its 117 at gain 10, and 2.55 draws 62 and 120 (4.6 and 2.6 percent off; the test in `test_drafts.py` renders flat frames and holds both to 10 percent). The dip uses the same multiply on the macro's even-stop keys (T23). The fit rests on that one dark frame: a bright frame, a look graded before the flash and Resolve's highlight roll-off were not measured, so the draft's note says so on every flash, and a first live run should compare one dark and one bright shot against an unflashed render.

- **T29. A transition is a track item.** `GetItemListInTrack` returns each dissolve as an item of its own, named "Cross Dissolve", with no media pool clip and False for every transform property. Raw item numbers after a dissolve are one higher than the manifest's span numbers, so an effect applied on `span_index + 1` of the raw list landed on the wrong item. Measured 2026-11-10 on a 48-span build with three dissolves: 51 items, and the outro's words belonged on items 45 to 51, not 42 to 48. `api.clip_items` is the one count: items with a media pool clip only, so transitions are skipped, and so are titles, generators and compound clips, which have no media pool item either. `vertical_apply` and `apply_effect` both number items with it, so `items` is a clip number from 1 and `span_index + 1` is right again; `apply_effect` also takes `spans` (the manifest's own indices, from 0) and records the raw track position in each target row. A transition item is never a target, so it cannot reach `AddFusionComp`. `timeline_items` lists the raw track, dissolves included: its `index` is the raw position and its `clip` is the clip number `items` takes (null for a dissolve). `apply_grade`, `stabilize` and `reframe_apply` still take raw positions. `vertical_apply` has skipped transition items since 2026-11-10 (before that it refused any timeline with a dissolve); `apply_effect` counted raw items until the same day.

## Framing

- **T6. Pan units.** Pan is measured against the fitted picture, the source scaled to the timeline by its input scaling before the item's zoom: Pan = shift x timeline width / fitted picture width, the shift being how far the picture moves in output pixels with the item's zoom already in it. Tilt is the same on the height with the opposite sign: the shift is measured y down and Resolve's Tilt is y up. Where the fitted picture spans the timeline (a 16:9 source on a 16:9 timeline) Pan is plain output pixels. `reframe.resolve_props` writes it this way, and for a 9:16 fill it comes to T15's (0.5 - crop centre) x 1080 x item zoom. An earlier wording multiplied by the item zoom beside a "scaled image width"; read as the fitted width that is an extra factor, which the code does not have (it cancels if the width is the zoomed one).
- **T7. Pan moves the Fusion output too.** At 16:9 a zoom's pivot and a title's merge centre go on the crop centre: 0.5 + (crop_x - 0.5) x (1 - timeline width / scaled width). Checked only in part: `reframe_apply` (16:9) writes Pan and moves no Fusion comp; it warns per item when it writes a Pan onto an item that has a comp (`GetFusionCompNameList`), and the formula is applied by hand. `vertical_apply` moves the `rp-fx` comps itself (T15). No code computes or reads back the 16:9 formula.
- **T15. 9:16 with fill.** Pan = (0.5 - crop centre) x 1080 x item zoom, written with the 9:16 timeline current (T27). Fusion comp space is the whole source frame, so a zoom pivot and a title centre sit at the crop centre itself. A title sized 0.14 at 16:9 becomes 0.048 at 9:16 for a seven-letter word at about 80 percent of the width. A word that pops from 60 percent to full over five frames must be judged on a late frame. A `person-matte-text` word moves the same way (`Text1.Center` x on the crop centre, size refitted), but its matte stays on the subject: the matte is a position in the source frame, and the crop does not move the subject.
- **T16. The face planner picks the face it can track.** That can be a bystander at the frame edge, a child included. Read every crop on a sheet before applying it. On one eight-video run, nine crops of 120 needed a hand-set centre.
- **T27. Pan and Tilt follow the current timeline.** `GetProperty` and `SetProperty` express an item's Pan and Tilt in the pixels of whichever timeline is current, not the timeline the item sits on. Measured 2026-11-10: one item on a 1080x1920 timeline read Pan -378.0 with a 3840-wide timeline current and -106.3125 with its own timeline current (ratio 1080/3840). A pan written under the wrong timeline lands at that ratio of the shift asked for, and a read-back taken in the same state passes. Make the item's timeline current before writing or reading framing, and prove a crop on a rendered frame (T26). `vertical apply`, `reframe_apply` and the `cut` aspect build do this since 2026-11-10.

## Color and Camera Raw

- **T19. A grade travels as a `.drx`.** `Timeline.GrabStill()`, then `GalleryStillAlbum.ExportStills([still], folder, prefix, "drx")` writes `<prefix>_1.1.1.drx`. `Graph.ApplyGradeFromDRX(path, 0)` on another item returned True and the item's CDL read back identical. The call replaces the item's whole graph. Not tested: whether windows, a tracked mask or noise reduction survive the trip.
- **T20. BRAW decode.** A BRAW clip's properties expose `ISO`, `White Point (Kelvin)`, `White Balance Tint`, `Input Color Space` and `Input Gamma`. No property names Decode Using. Setting it to Clip stays a computer-use step.
- **T21. Magic Mask needs a stroke.** `TimelineItem.CreateMagicMask("F")` returned False at once on an item nobody had drawn on. A person matte made outside Resolve ([cutout](reel.md)) needs no click.
- **T30. An untagged clip keeps Rec.709.** In a colour-managed project a clip with no Input Color Space tag reads a Rec.709 space and is decoded as display video. A V-Log file left that way renders in log, flat and grey, and no read-back catches it, because the clip's tag reads back exactly as it was left. `deliver_check` has a `log_flat` row for the render: five sampled frames that never reach near black or near white FAIL it, whatever the tags say (a heuristic; a flat look on purpose fails too). Measured 2026-11-10: a render pair of V-Log footage came out in log before anyone looked. A log source needs its Input Color Space set before it is graded or rendered; `ingest` does that for its own imports from what `detect` found. `assemble_timeline` now does the same for the files it imports itself (Input Color Space and Data Level, written and read back, on a colour-managed project only), lists in its dry run what `detect` says and what a clip already in its `methods [auto]` bin reads. It tags a clip it imports, a file that also sits in another bin included (the run imports its own copy, which is the clip that renders), and never rewrites a clip that was in the pool before the run, checked by clip id: one that is log by `detect` and reads Rec.709 is a problem line, and the timeline is left in place. A source `detect` cannot pin gets a note and no tag; tag it by hand. The look is a second half of the same rule. The draft farm draws with a camera cube (`<look> [<camera>].cube`), while a colour-managed build takes the look's `[RCM]` cube; the two are not interchangeable, and one edit uses one camera profile.

## Delivery

- **T17. A music montage has no captions.** A destination that wants captions (sidecar or burn-in) refuses a timeline with none. `social_9x16` alone carries a 29.97 fps floor (`min_fps` 30000/1001 in `resolve-config.json`): a lower rate gets a `deliver_check` WARN and a `queue_render` plan warning, never a refusal. `social_9x16_music` has no captions and no floor. Use `social_9x16_music`, or queue a master at 1080x1920 and transcode it: libx264 crf 16 preset slow, yuv420p, AAC 320k, two-pass loudnorm to -14 LUFS (`delivercheck.loudnorm_filter`), `+faststart`. Tag colour with `-x264-params colorprim=bt709:transfer=bt709:colormatrix=bt709`; the `-color_primaries` and `-color_trc` output flags left both unknown.
